# 开发接入说明

本 PR 是设计交付，不自动接管正式项目。请将其作为页面、组件和交互规则的评审基线，逐模块接入现有正式前端与服务端；保留现有账号、数据及接口行为。以下源码位置依据本 PR 基线 `f13d125` 只读核对，不能当成接口兼容性已经验证。

## 建议接入顺序

1. 从 `base.css` 提取颜色、字号、间距、边框和外观变量，采用组件作用域引入。勿全局覆盖正式页面样式。
2. 对接 `index.html` 的双端框架、导航与校园素材。正式角色由服务端会话决定；原型右上角的演示角色切换器不进入生产界面。
3. 将语言与外观控件接到正式偏好服务。三种语言可循环切换，外观保留系统跟随、键盘操作、选中提示和减少动画偏好。
4. 先接通任务→项目→提交快照→教师反馈→重交流程，再依次接入知识、论文/写作、团队竞赛和工具模块。
5. 接口完成后验证权限、版本、错误恢复和真实数据展示，再进行双端三语与明暗视觉验收。

## 已确认的权限与数据关系

- 学生可以自主创建项目、个人练习；教师发布教学任务。学生开始任务时可新建或关联个人项目；教师只看到学生主动提交的成果快照。重交新增版本，保留历史快照和反馈。
- 教师仅查看所带团队的任务提交、明确共享资料和约定的任务统计。个人项目、文稿、AI对话、个人修改清单及备注默认不共享；不统计学习时长。
- 教师原评语保留。学生手动将反馈加入个人清单并自勾完成，自勾不表示教师认可。新版本可选择带入未完成项，另填重交说明。
- 教师发布任务时设置截止与补交规则；退回修改另设重交截止。发布后的要求或时间变更先确认并通知相关学生，保留变更记录，不改写已有快照；已评阅不自动表示通过。
- 论文原件保留。改写产生关联文稿，支持草稿与命名版本；导出或提交前由学生确认，不覆盖原论文。
- 模拟竞赛支持个人和团队。队长创建、邀请、设规则、分工并开始或结束；成员更新分工、查看明确共享成果并讨论。关闭页面或离线不暂停，到时锁定已保存成果；后续练习复制新记录。
- 成绩CSV沿用 `email,assessment,assessmentDate,score,maxScore,source` 六列：预览并校验，仅导入所带团队学生；完全重复跳过，冲突阻止整批，不静默覆盖。
- 提醒仅面向有权团队内已验证且同意接收的学生；手动确认或计划执行时再次检查权限和接收意愿，显示跳过和发送结果。原型只模拟发送。
- 教师待办使用可解释优先级：逾期/临近截止、重交、普通待评阅；同类按等待时间。提供排序原因、可设置临近阈值，也可按提交时间查看。

## 演示数据替换与隔离

`core.js` 的 `seed()`、浏览器 localStorage、角色切换、演示附件、模拟异步结果和前端授权判断仅供设计评审。正式接入时应由现有服务取代这些部分，不迁移任何演示提交或成绩到真实数据中。不得将演示值 `123456`、`TEACH-DEMO` 当成真实验证或教师权限凭据。

系统界面语言与资料语言分离。翻译界面时，不自动翻译学生正文、教师原评语、资料名和引用来源。当前文案运行时用于独立原型；生产接入应按组件逐步替换为稳定文案键，并保留用户输入。

命名统一：真实教学身份称“教师”；工具称“AI 建模导师”；导航称“知识中心”，区分公共、个人、团队范围。建模八阶段中“论文评价”和“迭代优化”分别展示。

## 接入完成后需要共同确认

在真实登录环境中核验每个模块的接口、权限与保存结果；用真实异步服务检查加载、失败、重试和撤权状态；用长中文、英文和俄文在1440×900及1280/1920宽度下检查亮暗布局。原型内的前端权限表现不能当作服务端鉴权通过。
