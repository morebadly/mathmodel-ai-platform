# 论文格式与真实编译（2026-11-03）

## 使用方式

在论文实验室点击“撰写论文”，或在写作工作室点击“新建文稿”，填写标题并选择格式后开始写作。

| 格式 | 实际处理方式 | 输出 |
| --- | --- | --- |
| LaTeX | 已有 E2B 账号内的独立 TeX Live 环境；latexmk 调度 XeLaTeX、BibTeX/Biber | 真实 PDF、实际编译日志、可下载源码 |
| Markdown | 同源部署的 markdown-it、KaTeX 和 DOMPurify | 标题、表格、代码块、数学公式等实时预览及 .md 源码 |
| 普通文字 | 原文显示，保留换行，不执行 HTML 或解析排版命令 | 正文预览及 .txt 源码 |

已有文稿未设置格式时按普通文字兼容，不重写原稿、英文稿、修改记录或 AI 历史。格式选择在新建时完成；本轮没有跨格式自动转换。

中文原稿和英文文稿分别预览、保存；术语记录保留原来的用途。预览与此前的全屏按钮兼容。

LaTeX 停止输入约两秒后提交编译，同一界面只处理一项任务；编译过程中仍可修改源码，完成后再合并处理最新修改。可关闭自动编译，改为点击“立即编译”。编译过程包含排队和远程启动，不承诺逐键即时生成 PDF。本轮含中文和附件的完整样例从提交到完成约 20 秒，参考文献样例约 10–15 秒；这不是并发性能验收。

编译失败保留上一次成功 PDF，并明确标记源码已有修改。刷新或重新登录后可恢复本稿编译记录与最近成功预览。文稿或附件权限撤销后，旧 PDF 收起，可清空或重新选择附件再提交。

PDF 使用同源 PDF.js 绘制，不依赖浏览器内置 PDF 阅读器。测试所用 Edge 的内置 PDF 阅读器关闭，页面仍能显示编译 PDF。

## 实际能力与限制

- 默认模板使用 ctexart 与 Noto CJK 字体；已实测中文、数学公式、表格、两页 PDF、图片和 `\input` 文本附件。
- 已实测 BibTeX / natbib 与 BibLaTeX / Biber，参考文献由实际 .bib 文件生成。验收 .bib 是明确标记的合成样例，不是研究引用。
- 当前入口编辑一份主 .tex 文件。编译附件最多五份，输入和输出分别最多 10 MiB。选择文件后会显示 `input/0-文件名` 等实际引用路径；资源顺序保持选定顺序。
- 可从已有有权限的资料选择附件。上传入口增加 .cls、.sty、.bst、.bbx、.cbx。依赖文件需在当前 TeX 环境内或作为附件提供；不承诺任意比赛模板、字体及所有宏包兼容。
- 本轮没有实现完整 Overleaf 式目录项目、ZIP 工程导入、可视化同步定位或离线 LaTeX 编译。
- Markdown 是本地实时排版，不冒充 TeX 全文编译；普通文字不需要编译器。大模型与这三种格式的排版解耦，本轮未调用 AI 服务生成结果。

## 隔离、权限与额度

用户 TeX 不在 Django、Celery 或业务宿主机执行。E2B 为每个任务创建独立环境，关闭互联网访问；latexmk 禁用自动 rc 配置，XeLaTeX 禁止 shell escape，文件读写启用 `openin_any=p`、`openout_any=p`。

复用现有执行任务的持久化、状态、日志、取消、去重、输入 ACL、产物 ACL 和清理机制。LaTeX 任务绑定本人文稿与原稿/英文稿字段；账号、文稿与输入权限在创建、运行和下载时重新检查。编译附件纳入文稿保存、回收和恢复的依赖及统一锁顺序。

当前默认每账号每日 100 次 LaTeX 提交，使用 `LATEX_DAILY_JOBS` 调整；普通代码运行保留原有独立日限额。执行并发沿用 `SANDBOX_CONCURRENCY`，时限不超过服务端 `SANDBOX_MAX_SECONDS`。客户端遵循服务端时限。

LaTeX 会消耗已有 E2B 额度。本轮沿用已授权的 Hobby 账号，没有充值、升级或购买服务；没有把 E2B 密钥写入浏览器、仓库或镜像。正式扩大用户规模前，需要核算自动编译频率与额度。

| BibTeX / natbib | completed；真实参考文献条目出现在 PDF |

Edge 实际操作覆盖：三种格式新建、原稿/英文稿切换、Markdown 公式/表格/代码块、危险 HTML 和链接按安全方式处理、普通文字原样显示、保存与刷新、真实 PDF 分页、失败时保留旧 PDF、取消、全屏及手机布局。

后端回归：280 项运行，261 项通过，19 项跳过，零失败/错误。跳过项依赖 PostgreSQL/Redis 环境；本机没有将它们写成实测通过。新执行服务的模板、命令及状态协议测试属于合同/权限测试，上表是另外的真实 E2B 执行。

## 后续服务器部署

1. 复用现有 Django、数据库、execution worker 与 beat；不向业务镜像安装 TeX Live。
2. 在现有 E2B 账号中准备专用模板。本轮验收账号已建成模板；新环境可按下列命令构建。脚本只在 E2B 构建环境安装 TeX，不在本地执行业务源码。

```sh
python deploy/build_latex_template.py --name mathmodel-xelatex-v1 --env-file .env.local
```

凭证从后端 `E2B_API_KEY_FILE` 或 `E2B_API_KEY` 读取。模板含 XeLaTeX、ctex、Noto CJK、latexmk、BibTeX/Biber。

3. 在 web 和 execution worker 的环境变量中配置实际模板别名：

```dotenv
E2B_LATEX_TEMPLATE=mathmodel-xelatex-v1
LATEX_DAILY_JOBS=100
```

4. 随应用发布新的 JS/CSS 和 vendor 文件；保留现有 HTTPS、账号权限和资料卷。无需数据库结构迁移。
5. 在真实服务器验证出站 E2B、任务队列、中文 PDF、附件权限、取消和额度限制；服务器部署和负载尚未验收。本轮代码更新不会使现有公网网站自动升级。
6. 回滚前使用新版接口停止接收、取消或排空 LaTeX 任务，确认远端资源释放，再回滚前后端镜像；保留数据库、文稿和 PDF 文件，不删历史记录。旧代码不能调度新的 latex runtime 队列，因此不能带着待执行 latex 任务直接回滚。

未来自建沙箱可继续实现现有 gateway 的 latex runtime 协议；当前没有把自建环境标为通过。
